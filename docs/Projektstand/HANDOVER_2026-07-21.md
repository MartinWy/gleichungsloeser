# Handover 2026-07-21

## Wichtigster Punkt

Wenn im neuen Thread vom `Cockpit` die Rede ist,
ist damit die bisherige produktive Arbeitsform gemeint:

- lokaler Server auf `4173`
- echter Browser-Tab
- Eingabeseite rechts
- gerenderte Produktansicht links
- Gleichung eingeben
- Zielvariable setzen
- Schrittfarben waehlen
- live sehen, ob die Ausgabe stimmt

Es ist **nicht** gemeint:

- ein neues Interface-Experiment
- eine Simulation im Chat
- eine Codex-Seitenspalte statt echter Browserseite
- ein zweiter Renderpfad neben dem produktiven Standard

## Der richtige Link

Die App liegt standardmaessig hier:

```text
http://127.0.0.1:4173/
```

Wenn direkt ein Fall gezeigt werden soll,
werden Deep Links auf denselben Server benutzt:

```text
http://127.0.0.1:4173/?equation=...&targetVariable=...
```

## Was der Nutzer dort tun koennen muss

Der Nutzer muss dort unmittelbar:

- Gleichungen eingeben koennen
- die Zielvariable setzen koennen
- `Start / Go` druecken koennen
- links die fertige gerenderte Loesung sehen
- `PDF oeffnen` benutzen koennen
- Umformungsschritte ueber die Farbpalette faerben koennen
- sofort sehen koennen, wie die Farben in die Renderansicht eingehen

## Technischer Standard

Das Cockpit ist nur die Bedienhuelle.
Die mathematische und visuelle Wahrheit liegt weiter in:

- `core/index.js`
- `presentation/adapters/index.js`
- `components/Arbeitsblatt_Druckansicht/`
- `presentation/column_layout/`
- `scripts/export_projection_pdf_core/latexRendering.js`
- `scripts/cockpit_server.mjs`

Wichtig:

- `core/index.js` bleibt die einzige semantische Wahrheit
- das Cockpit darf keine zweite Solver-Logik aufbauen
- das Cockpit darf keine zweite Layout-Wahrheit aufbauen
- Cockpit, Vorschau, PDF und Arbeitsblatt muessen denselben Renderpfad benutzen

## Produktiver Serverpfad

Das Cockpit rendert ueber:

```text
POST /api/render
```

Zur Laufzeit entstehen dabei:

- `.cockpit-preview/current.tex`
- `.cockpit-preview/current.pdf`
- `.cockpit-preview/current.png`

Fuer Sichtpruefungen ist besonders wichtig:

```text
.cockpit-preview/current.png
```

Diese Datei ist die schnellste technische Kontrolle dafuer,
ob die linke Cockpit-Seite wirklich das zeigt,
was der Server zuletzt gerendert hat.

## Betriebsregel

Wenn der Nutzer sagt:

- `Go tut nichts`
- `die Felder leeren sich`
- `links bleibt ein alter Zustand stehen`
- `der Link wirkt falsch`
- `die sichtbare Ausgabe passt nicht zum Code`

dann gilt zuerst:

1. Server auf `4173` pruefen
2. wenn noetig frisch neu starten
3. danach die Seite auf `http://127.0.0.1:4173/` erneut oeffnen
4. `.cockpit-preview/current.png` mit der sichtbaren Ausgabe abgleichen

Nicht zuerst:

- neue UI erfinden
- einen Nebenport zum Standard erklaeren
- das Problem als mathematischen Core-Fehler deuten
